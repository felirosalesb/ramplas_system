2. MICROSOFT TEAMS WEBHOOK (Opcional)
════════════════════════════════════════════════════════════════════════════════

El sistema soporta notificaciones a Microsoft Teams, pero el webhook actual
es personal y debe ser reemplazado o removido.

📁 ARCHIVOS AFECTADOS:
   • src/environments/environment.ts
   • src/environments/environment.prod.ts
   • src/app/services/notification.service.ts

🔗 VALOR ACTUAL:
   ────────────────────────────────────────────────────────────────────────
   teamsWebhookUrl: 'TU_TEAMS_WEBHOOK_URL'
   ────────────────────────────────────────────────────────────────────────

📋 OPCIONES:

   OPCIÓN A: Configurar webhook corporativo
   ──────────────────────────────────────────────────────────────────────
   1. Ir al canal de Teams donde quieres recibir notificaciones
   2. Click en ⋯ (más opciones) → Connectors
   3. Buscar "Incoming Webhook" y configurar
   4. Copiar la URL generada
   5. Reemplazar en environment.ts y environment.prod.ts

   OPCIÓN B: Deshabilitar Teams (si no se usa)
   ──────────────────────────────────────────────────────────────────────
   1. En environment.ts y environment.prod.ts:
      teamsWebhookUrl: ''  // Dejar vacío
   
   2. En notification.service.ts (línea ~313):
      Comentar o remover la función enviarNotificacionTeams()
   
   3. Buscar todas las llamadas a enviarNotificacionTeams() y comentarlas

6. POLÍTICAS DE ROW LEVEL SECURITY (RLS)
════════════════════════════════════════════════════════════════════════════════

⚠️ CRÍTICO PARA SEGURIDAD ⚠️

El schema SQL incluye la estructura básica, pero las políticas RLS deben
ajustarse según las reglas de negocio específicas de la empresa.

📋 POLÍTICAS RECOMENDADAS:

   Ver README.md sección "Configuración de Row Level Security (RLS)"

📋 PASOS:

   1. Revisar políticas actuales en Supabase → Authentication → Policies
   2. Ajustar políticas según roles:
      • Planta: Solo sus propios tickets
      • CD: Todos los tickets
      • Galpón: Tickets de pallets vacíos
      • Admin: Acceso total
   3. Probar con cada tipo de usuario
   4. Documentar políticas finales

7. CONFIGURACIÓN DE REALTIME
════════════════════════════════════════════════════════════════════════════════

Supabase Realtime debe estar habilitado para que las actualizaciones en
tiempo real funcionen.

📋 PASOS:

   1. En Supabase → Database → Replication
   2. Habilitar Realtime para las siguientes tablas:
      ✓ tickets
      ✓ ramplas
      ✓ muelles
      ✓ notificaciones (opcional pero recomendado)
   3. Verificar en los dashboards que se actualicen automáticamente

8. VARIABLES DE ENTORNO EN PRODUCCIÓN
════════════════════════════════════════════════════════════════════════════════

Si despliegas en Vercel, Netlify u otro servicio, configura variables de
entorno en lugar de hardcodearlas en environment.prod.ts.

📋 VERCEL:
   ────────────────────────────────────────────────────────────────────────
   1. Ir a proyecto en vercel.com
   2. Settings → Environment Variables
   3. Agregar:
      - SUPABASE_URL = https://[proyecto].supabase.co
      - SUPABASE_KEY = [anon-key]
      - TEAMS_WEBHOOK_URL = [webhook-url] (opcional)
   4. Redeploy el proyecto

📋 NETLIFY:
   ────────────────────────────────────────────────────────────────────────
   Similar a Vercel, en Site Settings → Environment variables

⚠️ Nota: Requiere modificar environment.prod.ts para leer de process.env
